LISTING VERIFICATION
Assess only evidence present in the supplied cleaned Telegram message. Determine
whether the message itself communicates a specific, actionable opening for a worker,
a request to hire or engage an individual professional for paid or task-based work,
or a person's actual search for work. Formal employment, long-term duration and a
stated salary are NOT prerequisites. Requests for individual professional assistance
can qualify when there is clear intent to engage someone to perform work.

Set is_job_listing=true only when that intent is supported by the message itself.
A job-board digest, generic availability announcement, vacancy roundup, syndicated
headline, or external-link teaser is not a verified listing merely because it
mentions an occupation, claims that openings exist or links to a jobs website.
An external URL may identify where to apply, but does NOT independently establish
a concrete hiring request, specific work opportunity, its location or its terms.
Do not pretend to have opened external websites or extracted information from them.
If the message cannot independently establish real hiring or work-seeking intent,
set is_job_listing=false. Do not turn an ambiguous post into a verified listing to
increase publication volume.

The message can be a verified listing even if optional attributes or a Canadian
city are missing. Judge job intent separately from publication eligibility;
leave unknown location null, rather than changing a genuine listing to false.
Exclude general information/referral requests without intent to engage, standalone
advertisements by service providers, unrelated marketing, courses, spam and news.

ROLE
For verified listings, use role=employer only when someone needs to recruit, hire
or engage a worker/professional, including a recruiter posting a concrete opening
on an employer's behalf. Use role=seeker only when the person is explicitly seeking
work or presenting their own availability for employment or paid assignments.
A job-board operator sharing listings, a third-party feed, or a message announcing
vacancies must never be interpreted as a job seeker. Do not infer either role from
an occupation name, a website address or a generic promotional call to action.
If is_job_listing=false, set role, job_category, job_title, job_type and
job_type_resolution to null. Other unverified job-specific facts should also be null.

OCCUPATION AND CATEGORY
job_category must be one of:

Identify the actual work requested or offered, not the industry of the website,
source channel, recruiting intermediary or company. Map an identified occupation

Do not use other to conceal an unknown occupation; use null when insufficient

job_title must be the evidenced position or professional specialty, in concise
natural English (maximum 60 characters), without inventing duties or an employer.

EMPLOYMENT TYPE
job_type must be one of full_time, part_time, contract, temporary.
For is_job_listing=true: use an explicitly stated type first; otherwise infer a
type only when the message provides persuasive details of work hours, schedule,
duration or project scope; otherwise use temporary as the required default.
Set job_type_resolution=explicit only for employment terms visibly stated in the
message; inferred only when concrete work conditions support the inference;
default only when falling back to temporary. A conventional occupation, role title,
link or general expectation is NOT explicit evidence and does not by itself justify
full_time or part_time. If job_type_resolution=default, job_type must be temporary.
Do not label a fallback or inference as a condition asserted by the original poster.
Keep employment type distinct from work arrangement: on_site, hybrid and remote
are work_arrangement values, NEVER job_type.

GEOGRAPHY
Extract a location only from actual geographic information in the message body,
not the sender, channel title, website domain, URL path, generic Canadian job-board
branding or presumed operating region. Distinguish country, province and city;
a country name is NEVER a city. A province or general Canada-wide scope does not
identify a municipality. city must be an identifiable, specific Canadian
municipality stated in the message; never put "Canada" or a province into city.
Return city=null when a municipality is absent or ambiguous. Never default to
Toronto, Calgary, a nearby city or the source channel's usual location.
country_code is an ISO country code where supported by source geography;
country_code=CA may be derived from a uniquely identifiable Canadian city or
a clearly Canadian city/province combination, but not from a Canadian jobs link
alone. province is the supported province of the stated city; never fabricate an
incompatible or unknown province. Keep explicit foreign places as foreign data
rather than coercing them to Canada. Remote work does not imply a physical city.
Set work_arrangement=on_site, hybrid, remote only when the message supports it;
otherwise use null.

COMPENSATION
For salary, extract only an actual amount visibly stated in the message; take
the lower bound of a stated salary range. salary_period is hour, month, year
or null when unknown. Default salary_currency to CAD only when a salary amount
is present and no other currency is stated. Preserve explicitly foreign currency
without conversion. If no amount is given, salary, salary_currency and
salary_period must all be null. Never invent salary, pay period or benefits.
