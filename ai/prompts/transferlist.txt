## ROLE

`transfer_role` MUST be one of:

* `passenger`
* `shipper`
* `null`

`passenger` = the author is traveling and can carry another person's goods.

`shipper` = the author has goods and wants another person or service to transport them.

Priority:

1. Explicit offer to carry goods → `passenger`
2. Clear travel/flight with cargo capacity → `passenger`
3. Author has goods and needs transportation → `shipper`
4. Otherwise → `null`

Never determine the role from a single keyword such as flight, date, airport, route, cargo, or post.

If `transfer_role = null`, the application must NOT save the record.

## ROUTE

`origin_city` = departure/loading/source city.

`destination_city` = arrival/unloading/target city.

Preserve the source direction. Never reverse it.

Each field must contain exactly ONE city.

If multiple cities appear on one side, select the primary/base city using the main route or major metropolitan city. Never concatenate cities.

If multiple independent routes exist and no dominant route is clear, use `null`.

## LOCATION STANDARD

Cities: standard internationally recognized English/Roman form.

Countries: ISO 3166-1 Alpha-2 uppercase.

Province: extract only when explicitly stated or confidently identifiable.

Do not include flags, emojis, airport codes, UN/LOCODE, URLs, or hashtags in location fields.

## DATES

Extract explicit travel, departure, arrival, delivery, or shipment dates as Gregorian `YYYY-MM-DD`.

The application provides the current date.

If the year is missing, assume the date belongs to the current month unless another year is explicitly stated.

Recognize Persian/Jalali dates and convert them to Gregorian.

If a date clearly belongs to a flight/travel route and no arrival date exists, use it as `departure_date`.

Never invent dates or times.

## TRANSPORT

`transport_type` MUST be one of:

* `air`
* `ground`
* `sea`
* `null`

Use `air` for air transportation, `ground` for road/rail transportation, and `sea` for maritime transportation.

`post` alone does not determine transport type.

## CARGO / PRICE / TRAVEL

Extract only information explicitly supported by the source.

Extract cargo type, weight, unit, quantity, volume, and unit only when stated. Never estimate or calculate.

Extract price only when explicitly stated.

Currency: ISO 4217 code. Use the explicitly stated currency; if omitted, infer it from the route only when confidence is high. Never convert the price.

Extract airline, flight number, and times only when explicitly stated.

Extract explicit contact information only.

Use `features` only for additional explicit transfer information not covered by other fields.

## DESCRIPTION

`description` MUST be the original source message.

Do NOT translate, summarize, rewrite, paraphrase, shorten, correct, or modify it.

Preserve the original language, wording, spelling, punctuation, and emojis.

## TITLE

Prefer a concise route-based title when the route is known.

Do not invent information.

## NO GUESSING

Allowed normalization only:
